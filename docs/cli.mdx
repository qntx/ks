## Global options

| Option | Effect |
| --- | --- |
| `--vault <dir>` | Vault directory (`KS_VAULT`; default `~/.ks`) |
| `--json` | One JSON object on stdout, nothing else |
| `--passphrase-file <f>` | Master passphrase from a file (`KS_PASSPHRASE_FILE`) |
| `--no-agent` | Do not use (or start) the session agent |
| `-V`, `--version` | Print version |

Environment: `KS_VAULT`, `KS_PASSPHRASE`, `KS_PASSPHRASE_FILE`,
`KS_NEW_PASSPHRASE_FILE` (new passphrase for `init`/`passwd`/`rekey`),
`KS_CLIP_TIME` (clipboard lifetime in seconds, default 45),
`VISUAL`/`EDITOR` (`edit`), `GIT_TERMINAL_PROMPT=0` is always set by ks.

## Commands

| Command | Usage | Command-specific options |
| --- | --- | --- |
| `init` | `ks init` | `--git` init a repo; `--clone <url>` clone instead; missing parent directories are created |
| `ls` | `ks ls [prefix]` | — |
| `show` | `ks show <name>` | `-f <field>` print one field; `-c` copy to clipboard |
| `set` | `ks set <name>` | `-m` multiline from stdin; `-b` raw bytes from stdin; `--force` overwrite |
| `edit` | `ks edit <name>` | — (needs a terminal; binary entries → usage) |
| `gen` | `ks gen [name]` | `-s <set>` (alphanum\|hex\|printable\|slug, default alphanum); `-c` copy; `--force` overwrite |
| `rm` | `ks rm <name>` | `--force` no confirmation |
| `mv` | `ks mv <from> <to>` | `--force` overwrite destination |
| `otp` | `ks otp <name>` | `-c` copy code to clipboard |
| `run` | `ks run -e <var=name[#field]>… -- <cmd>` | `-e` repeatable env mappings |
| `passwd` | `ks passwd` | — (K unchanged; use `rekey` to revoke) |
| `doctor` | `ks doctor` | `--fix` remove temp files, fix perms + git metadata |
| `sync` | `ks sync` | `--keep local\|remote` retry a conflicted rebase |
| `rekey` | `ks rekey` | — (needs a NEW passphrase) |
| `unlock` | `ks unlock` | `--ttl` idle timeout (default 15m); `--max` lifetime cap (default 8h, max 24h) |
| `lock` | `ks lock` | — |
| `status` | `ks status` | — |
| `touchid` | `ks touchid <enable\|disable>` | — |
| `keychain` | `ks keychain <enable\|disable>` | — |
| `git` | `ks git <args…>` | passthrough inside the vault |

> `ks run` note: injected values are visible to same-user processes via
> the child's environment (e.g. `/proc/<pid>/environ` on Linux). Use `run`
> only with commands you trust; prefer pipes/stdio for sensitive flows.

## JSON shapes

```jsonc
// ks status --json
{ "vault": "/path", "agent": {"ttl_left": 900, "life_left": 28000} | null,
  "touchid": false, "keychain": false,
  "git": {"repo": true, "dirty": false} }
// ks unlock --json            ks lock --json          ks rekey --json
{"unlocked":true,"ttl":900,"max":28800}   {"locked":true,"was_running":true}
{"rekeyed":true,"resumed":false,"entries":12}
// ks sync --json    ks touchid/keychain enable --json      disable
{"committed":true,"pulled":true,"pushed":true}   {"enabled":true}  {"disabled":true,"was_enabled":true}
// errors: {"error":"locked","message":"vault is locked"} on stderr-side channel
```

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | success |
| 64 | usage / invalid input |
| 65 | corrupt vault file, or weak passphrase |
| 66 | entry not found |
| 69 | external tool/service unavailable (git, age-plugin-se, keychain) |
| 70 | internal error / cancelled |
| 73 | entry already exists |
| 74 | I/O error |
| 75 | sync conflict (retry with `--keep`) |
| 77 | locked (unlock again — also after a key rotation raced your command), or wrong passphrase |
