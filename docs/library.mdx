---
title: Library
description: The ks crate — open, unlock, read and write a vault from Rust.
---

```toml
[dependencies]
ks = { version = "0.8", features = ["agent", "keychain"] }
```

Features: `agent` (session-agent client over `interprocess`), `keychain`
(OS keychain factor, macOS/Windows). Touch ID needs no feature — it is
always compiled, and `enable` reports `Unavailable` off macOS.

```rust,no_run
use ks::{Entry, Name, Vault};
use zeroize::Zeroizing;

let vault = Vault::open("~/.ks".as_ref())?;
// `unlock(None)` tries the agent, Touch ID and the keychain; pass a
// passphrase source for the final step:
let session = vault.unlock(Some(&|| {
    Ok(age::secrecy::SecretString::from("correct horse …"))
}))?;
for w in session.warnings() { eprintln!("warning: {w}"); }

let name = Name::parse("github/token")?;
let entry = session.get(&name)?;
let token = entry.as_text().unwrap().value();

session.set(&name, &Entry::text(Zeroizing::new(
    "ghp_…\nuser: octocat".to_owned()))?, true)?;
```

`Session::get/set/remove/rename` take the vault write lock and do atomic
writes; `vault.list(None)` enumerates names without unlocking;
`vault.rekey(pass, &new_pass)` rotates the key. With only `feature =
"agent"` off, `vault.unlock` skips straight to device factors/passphrase.

Everything the library does is on plain files — nothing the CLI can do
is unavailable to embedders, except the CLI's own prompts/hardening.
